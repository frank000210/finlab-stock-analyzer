# 官方開放資料倉庫（證交所／櫃買／集保 → 自己的 MongoDB）

每天晚上 21:30（台灣時間，含週末）自動把證交所、櫃買中心、集保的**公開資料**抓下來，存進自己的 MongoDB（`od_*` 集合）。
目的：不佔 FinMind 額度（每小時 600 次）；官方多半只給「最新一份」，自己存起來歷史就會一天一天累積；集保檔案又大又常連不上，改成每週抓一次存起來。

和「每日資料庫」（`docs/每日資料庫.md`，`md_*` 集合）互補、不重疊：那個是**白名單股票、來源 FinMind**；這個是**全市場、來源官方**。

## 存什麼

| 資料集 | 集合 | 來源 | 唯一鍵 | 一天約多少筆 |
|---|---|---|---|---|
| `margin` 融資融券 | `od_margin` | 證交所網頁版 JSON（帶日期）＋櫃買 OpenAPI | symbol + date | ≈ 2,230 |
| `valuation` 本益比／淨值比／殖利率 | `od_valuation` | 證交所 OpenAPI `BWIBBU_ALL`＋櫃買 OpenAPI | symbol + date | ≈ 1,980 |
| `revenue` 月營收 | `od_revenue` | 證交所 OpenAPI `t187ap05_L`＋櫃買 OpenAPI | symbol + ym | 每月 ≈ 1,970 |
| `disposal` 處置股公告 | `od_disposal` | 證交所 `announcement/punish`＋櫃買 | symbol + date + start | 個位數～數十 |
| `attention` 注意股公告 | `od_attention` | 證交所 `announcement/notice`＋櫃買 | symbol + date | 0～數十 |
| `tdcc` 集保股權分散表 | `od_tdcc` | 集保開放資料 `getOD.ashx?id=1-5`（CSV） | symbol + date | 每週 ≈ 4,115 |

- 上市（`mkt=twse`）與上櫃（`mkt=tpex`）放在同一個集合，欄位一致，用 `mkt` 區分。
- 另有 `od_state`（每個資料集最後成功時間、資料日期、各來源結果）與 `od_runs`（最近 60 輪的執行紀錄）。
- **欄位**（單位沿用官方）：融資融券 `margin_buy／sell／repay／prev／bal／limit`（融資）、`short_cover／sell／repay／prev／bal／limit`（融券）、`offset`（資券互抵）；估值 `pe／pb／dy`（本益比、淨值比、殖利率%）；月營收 `rev／mom／yoy／cum／cum_yoy`（千元、%）、`report_date`（出表日）；集保 `lv`（第 1～15 級的 [人數, 股數, 占比%]）、`pct_400plus／holders_400plus`（400 張以上）、`pct_1000plus／holders_1000plus`（1,000 張以上）、`total_holders／total_shares`。
- 每份文件有 `first_seen`＝**我們第一次抓到的那天**（只在新增時寫入）。回測時用它當「最早可知日」，不能用資料所屬日期偷看未來。

## 做法與守則（寫在程式裡，不只是文件）

1. **只打官方開放資料接口**，不爬網頁、不碰要驗證碼的頁面（例如券商分點，不處理、不繞過）。
2. **融資融券的證交所部分用網頁版 JSON（帶日期參數）**：開放資料版本沒有日期欄位，而且實測會比網頁版晚一天（11/12 晚上開放資料還是 11/11 的數字），直接存會把昨天標成今天。程式每天往前看 5 個平日，補上還沒存的日期；假日回「沒有符合條件」就記起來不再問；當天還沒公布的明天再問。
3. **誠實的 User-Agent**（`finlab-stock-analyzer/1.0 (personal research; once-daily; low rate)`），任兩個請求至少隔 1 秒，每天只跑一輪（約 11～15 個請求），失敗最多重試 2 次。
4. **被擋就停**：HTTP 403／429、防火牆頁面、「查詢過於頻繁」這類訊息，立刻停止整輪並**冷卻 6 小時**（手動觸發也一樣），不重試、不換標頭、不繞過。
5. **網址改版要報得出來**：不跟隨轉址、404 直接報錯（舊網址默默轉走正是爬蟲常見的壞法）；欄位少了、筆數遠低於正常（例如融資融券 < 800、集保 < 2,000 檔）、原始資料有但幾乎解析不出來，都**不寫入**並記錄原因。
6. **冪等**：先建唯一索引再 upsert，重跑不會重複；內容沒變時 Mongo 不真的寫入（所以文件裡不放更新時間）。
7. **一個來源失敗不影響其他**；一個資料集只有在「上市＋上櫃都成功」才算新鮮（少半個市場的資料不能說新鮮）。

## 怎麼用

```bash
# 健康檢查（公開）：各資料集 ok／partial／stale／error／never
curl https://<host>/api/v1/open-data/health

# 狀態：各集合筆數、各來源最後結果、最近 10 輪（管理員）
curl https://<host>/api/v1/open-data/status -H "X-Admin-Token: <token>"

# 馬上跑一輪（背景執行；datasets 可只挑幾個；force 讓集保不略過）
curl -X POST https://<host>/api/v1/open-data/run -H "X-Admin-Token: <token>" \
  -H "Content-Type: application/json" -d '{"datasets":["margin","tdcc"],"force":false}'

# 讀單一股票的已存資料（公開、唯讀、由舊到新）。月營收的日期欄位是 ym，其他是 date
curl "https://<host>/api/v1/open-data/data/margin/2330?start=2026-11-01&limit=60"
curl "https://<host>/api/v1/open-data/data/tdcc/2330?limit=10"
```

健康判斷：`stale`＝超過 3 天沒成功，或資料日期落後（融資融券／估值 > 5 天、集保 > 14 天；多抓了長假的餘裕）；`error`＝只有失敗沒有成功過；`partial`＝最近一輪有來源失敗；`never`＝還沒跑過。

## 排程

app 啟動 2 分鐘後，若任何資料集從沒成功或超過 30 小時沒成功，補跑一次；之後每天 21:30 台灣時間（含週末，因為集保是週資料、常在週末更新）。集保已存的最新一份不到 7 天就略過。

| 環境變數 | 預設 | 說明 |
|---|---|---|
| `OPEN_DATA_ENABLED` | `true` | `false` 關閉自動排程（手動 `/run` 仍可用） |
| `OPEN_DATA_HOUR` / `OPEN_DATA_MINUTE` | `21` / `30` | 台灣時間 |

## 容量

實測平均文件大小：融資融券約 300 B、估值約 130 B、月營收約 290 B、集保約 700 B。每年累積約 165 + 63 + 7 + 150 MB ≈ **0.39 GB（未壓縮）**，加索引與壓縮後磁碟約 0.25 GB／年。MongoDB 快取只有 0.25 GB，查「單檔歷史」走索引沒問題；之後若要整個市場掃描一年以上，需要再評估或定期封存舊資料。

## 限制（誠實說）

- **歷史從開始跑那天起累積**。官方開放資料多半只有最新一份；融資融券（證交所）第一輪會補到近 5 個平日，其餘從第一天開始。要回補更久的歷史需要另外用帶日期的歷史端點，慢慢補。
- 上市與上櫃的資料日期可能差一天（例如證交所估值 11/11、櫃買 11/12），各自記自己的日期，不混。
- 不含券商分點、借券、當沖、財報三表（損益表／資產負債表在開放資料中是「依產業別」的快照，下一步再評估）。
- 目前**只存不讀**：現有頁面（評分卡、ETF 比較等）還是各自抓 FinMind。下一步是讓它們「先讀這裡、沒有再抓 FinMind」，例如評分卡籌碼面的集保與融資項目、事件旗標（處置／注意）。

程式：`backend/app/data/open_data.py`（抓取、解析、排程邏輯）、`backend/app/api/open_data.py`（API）、排程在 `backend/app/scheduler.py`；測試：`backend/tests/test_open_data.py`（46 項）、`e2e/tests/open-data.spec.js`。

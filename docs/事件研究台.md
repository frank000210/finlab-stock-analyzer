# 事件研究台（/events）

把「看新聞、聽別人分析、看技術面、做決定」這件事拆成固定的步驟。它幫你把功課做完整，**不預測漲跌、不給買賣建議**。

核心觀念是三層要分開：

| 層 | 問的問題 | 在這裡對應什麼 |
|---|---|---|
| 事實 | 到底發生了什麼？ | 簡報的「事實」，每一則標來源分級與是否已證實 |
| 解讀 | 對誰有影響、多大、多久？ | 影響地圖、三個情境、各方觀點、論點抽取 |
| 決策 | 我要不要動作、錯了怎麼辦？ | 我的決策紀錄（只存在你的瀏覽器） |

## 四個功能

### 1. 事件日曆

- **內建事件**（`backend/app/data/event_calendar.json`）：聯準會 FOMC、美國 CPI 與就業報告、重點公司財報。
  每一筆都有官方來源網址與查證日期（`verified_on`）。目前查證於 2026-11-14。
- **台股休市日**：照臺灣證券交易所「市場開休市日期」原樣存，涵蓋 2026-11-14～2027-12-31。連假會併成一段，標出少幾個交易日、哪天恢復。
- **法定公告期限**（規則推算）：每月 10 日前公告上月營收；季報 5/15、8/14、11/14，年報 3/31（證券交易法第 36 條）。遇假日順延。
  這是期限，不是個別公司的實際公告日。
- **簡報的關鍵日期**：每份事件簡報列的後續日期會自動出現在日曆上，並連回簡報。跟內建事件是同一件事（同一天、同一個來源網址）時只列一筆。
- **自訂事件**（管理員）：例如某檔股票的法說會。存在 MongoDB `ev_calendar`。
- **台股最快反應日**：美國時間的事件都落在台股收盤後，日曆會標出下一個台股交易日（遇連假往後推）。

預設顯示 3 天前到 120 天後；API 可指定範圍，最長 400 天。

### 2. 事件簡報

每份簡報固定六塊，另有價格反應與各方觀點：

1. **事實**：`tier` 1 官方第一手／2 媒體／3 評論與社群；`confirmed: false` 代表「有人這樣報導，但沒有官方或當事人證實」。
2. **預期對照**：事前已反映什麼、實際發生什麼、落差在哪。市場反應的是落差。
3. **影響地圖**：直接、二階（供應鏈與客戶）、三階（資金面、評價、政策）。每一項要寫傳導機制、反映時間、把握度。這是解讀，不是事實。
4. **三個情境**：基準／樂觀／悲觀，各自寫「看到什麼代表往這裡走」與「看到什麼代表不成立」。
5. **後續關鍵日期**。
6. **還不知道的事**。

**完整度檢查**（規則式，9 項）只看流程有沒有漏步驟：有沒有第一手來源、來源是否來自 2 個以上獨立網域、預期對照是否填完、
有沒有二三階影響、三情境是否齊全且都有推翻條件、有沒有後續日期與未知事項。它不判斷觀點對錯。

**簡報的兩種來源**

- 內建：`backend/app/data/event_briefs/<id>.json`，隨程式版本發布，檔名要等於 `id`，不能在網站上覆寫或刪除。
  單元測試會檢查每個檔案格式正確且完整度滿分。
- 管理員建立：事件研究台「事件簡報」分頁最下方的編輯器（JSON），或直接呼叫 API。存在 MongoDB `ev_briefs`。
  流程是「載入空白模板 → 填寫 → 檢查格式 → 存檔」。

網址欄位只接受 `http://`／`https://`（會被放進連結，擋掉 `javascript:` 之類）。

### 3. 價格反應（事後量測）

簡報設了 `tw_base_date`（台股「事件前最後一個交易日」）且影響地圖裡有台股代號時，可以按「計算價格反應」：

- 事件後第 1 天與至今的漲跌（以基準日收盤為準）、減掉加權指數後的差。
- 設了 `episode_start`（醞釀期起點）時，另外算「事前」已經漲跌多少、期間最低到哪。
- 第 1 天成交量相對事件前 20 日均量的倍數；最新收盤在月線（20 日）、季線（60 日）之上或之下。

每檔 1 次 FinMind 呼叫（最多 20 檔＋大盤），按了才抓，結果快取 6 小時；抓不齊時只快取 30 分鐘。
美股代號不計算（事實欄位裡已有來源數字）。

**一兩天的漲跌雜訊很大，不能拿來證明影響地圖是對的**——這件事登記為待驗主張 C13（`docs/待驗主張清冊.md`），目前事件數不足，無法驗證。

### 4. 論點抽取

貼上財經影片逐字稿或文章（200～20,000 字），AI 拆成最多 8～10 條論點，每條標示：

- 類型：事實陳述／預測／意見
- 靠什麼假設
- 推翻條件：講者有沒有說「什麼情況下他會改口」（沒說就顯示「講者沒說」，不替他補）
- 怎麼驗證

**防止 AI 編造**：提示詞要求每條論點附一句逐字照抄的原句；後端再核對這句話是否真的出現在你貼的文字裡
（忽略空白與標點）。結果分三種：原文找得到／有近似句子（斷句不同）／找不到。找不到的會用紅色標出。

本站不自動抓取 YouTube 內容（官方字幕介面需要影片擁有者授權，爬取違反服務條款）；請自己從影片的「顯示轉錄稿」複製。
呼叫 LLM 會套用全站的每 IP 10 分鐘 6 次限制與每日總量上限；內容太短或太長被擋下時不計次。相同內容 6 小時內不重複呼叫。

### 我的決策紀錄

在簡報頁最下方。動作之前先寫：打算怎麼做（含「不動作」）、理由、最多可承受虧損（占總資金 %）、什麼情況代表看錯、哪一天回頭檢討。
到了檢討日，事件研究台首頁會提醒。**只存在瀏覽器的 localStorage**（鍵 `finlab_event_decisions_v1`），伺服器不保存；
換瀏覽器或清除資料就沒了。具體一筆單的部位大小用「部位風控」，成交後記到「交易日誌」。

## API

| 方法與路徑 | 權限 | 說明 |
|---|---|---|
| `GET /api/v1/events/calendar?start=&end=&category=` | 公開 | 日曆；`category` 可用逗號分隔多個 |
| `POST /api/v1/events/calendar` | 管理員 | 新增自訂事件 |
| `DELETE /api/v1/events/calendar/{id}` | 管理員 | 只能刪自訂事件（`c-` 開頭） |
| `GET /api/v1/events/briefs` | 公開 | 簡報列表（含完整度） |
| `GET /api/v1/events/briefs/template` | 公開 | 空白模板與欄位說明 |
| `POST /api/v1/events/briefs/validate` | 公開 | 只檢查格式與完整度，不存檔 |
| `GET /api/v1/events/briefs/{id}` | 公開 | 單份簡報＋完整度 |
| `PUT /api/v1/events/briefs/{id}` | 管理員 | 新增或修改（內建 id 回 409） |
| `DELETE /api/v1/events/briefs/{id}` | 管理員 | 刪除（內建 id 回 409） |
| `GET /api/v1/events/briefs/{id}/reaction` | 公開 | 價格反應（會打 FinMind，有快取） |
| `POST /api/v1/events/claims/extract` | 公開（有限流） | 論點抽取（呼叫 LLM） |

MongoDB 壞掉時，日曆與簡報仍會回內建資料。

## 維護

- **日曆要定期重查**：`event_calendar.json` 的日期來自聯準會、美國勞工統計局、交易所、公司投資人關係網站。
  聯準會註明每次會議日期在前一次會議確認前都是暫定；勞工統計局註明時程會視需要更新。改日期前先重查官網，並更新 `verified_on`。
- **休市日每年底補下一年**：交易所網址 `https://www.twse.com.tw/rwd/zh/holidaySchedule/holidaySchedule?response=json&date=YYYY0101`。
  「開始交易日／最後交易日」這類標記列不是休市，不要放進 `tw_market_closed.days`。
- **新增內建簡報**：在 `backend/app/data/event_briefs/` 放一個 JSON，檔名等於 `id`，跑 `backend/tests/test_event_desk.py`。

## 限制

- 個別公司的法說會日期沒有可合規批次取得的官方來源（證交所開放資料沒有這個資料集），要手動新增。
- 影響地圖與情境是人寫的解讀，可能是錯的；完整度滿分不代表觀點正確。
- 價格反應只算台股日線，沒有盤中、沒有美股。
- 論點抽取的品質取決於 LLM 與逐字稿品質；語音轉文字的錯字會讓原句比對落到「近似」或「找不到」。
- 簡報編輯器是 JSON，沒有表單。
- 決策紀錄不跨裝置。

  價格反應的基準日與超額計算、引文比對、LLM 輸出整理與快取。不連資料庫、不碰網路、不呼叫 LLM。

  決策紀錄與到期提醒、論點抽取、Ctrl+K 搜得到、手機寬度（含很寬的價格反應表）不左右捲動。價格反應與論點抽取在畫面測試裡用假回應，不消耗額度。

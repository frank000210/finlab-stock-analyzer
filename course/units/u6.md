# U6 評測、護欄與部署：Hooks

> **Agent 原理**：Agent 會出錯，也可能被外部內容誘導。可靠的系統需要**模型之外**的確定性控制：護欄、自動檢查、品質關卡。
> **Claude Code 實作**：Hooks（PreToolUse、PostToolUse 等生命週期事件）、exit code 2、JSON 決策輸出。
> **本課實作**：擋危險指令、自動格式化，以及「讀過外部內容後降級」的護欄。

## 請求 vs 強制

前面學過的 CLAUDE.md、skill、output style，全都是**給模型的指示**。模型通常會遵守，但不保證。

官方文件的說法很直接：在 CLAUDE.md 寫「絕對不要改 `.env`」是一個**請求**；用 `PreToolUse` hook 擋下這個編輯才是**強制**。

| | 指示（CLAUDE.md / skill） | Hook |
|---|---|---|
| 誰執行 | 模型決定要不要照做 | Claude Code 在事件發生時一定執行 |
| 結果 | 可能有例外 | 確定性的 |
| context 成本 | 每次都佔用 | 零（除非 hook 回傳內容） |
| 適合 | 需要判斷的工作流程、知識 | 一定要做到的規則、自動化 |

**一條規則如果每次都必須成立，就把它寫成 hook，不要寫成提示詞。**

## Hook 是什麼

Hook 是你寫的指令（通常是一支腳本），在 Claude Code 生命週期的特定時間點自動執行。設定寫在 settings 檔的 `hooks` 裡：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx prettier --write \"$(jq -r '.tool_input.file_path')\"" }
        ]
      }
    ]
  }
}
```

這段的意思：每當 Claude 用 Edit 或 Write 工具改完檔案，就用 prettier 格式化那個檔案。

設定位置決定範圍：

| 位置 | 範圍 |
|---|---|
| `~/.claude/settings.json` | 你所有的專案 |
| `.claude/settings.json` | 這個專案，可以進版控給團隊 |
| `.claude/settings.local.json` | 這個專案，只有你 |
| Plugin 的 `hooks/hooks.json` | 啟用該 plugin 時 |
| Skill 或 subagent 的 frontmatter | 該 skill 被呼叫後／該 subagent 執行期間 |

輸入 `/hooks` 可以瀏覽目前所有生效的 hook。

## 常用的 hook 事件

| 事件 | 觸發時機 | 典型用途 |
|---|---|---|
| `SessionStart` | session 開始或恢復時 | 注入當天的背景資訊 |
| `UserPromptSubmit` | 你送出訊息、Claude 處理之前 | 檢查或補充提示詞 |
| `PreToolUse` | 工具執行**之前**，**可以擋下** | 擋危險指令、保護檔案 |
| `PermissionRequest` | 需要權限決定時 | 自動核准特定請求 |
| `PostToolUse` | 工具**成功執行之後** | 格式化、lint、記錄 |
| `Notification` | Claude Code 發通知時（例如等你回應） | 桌面通知 |
| `Stop` | Claude 回應結束時 | 最後的品質檢查 |
| `SubagentStop` | subagent 結束時 | 檢查 subagent 的成果 |
| `PreCompact` / `PostCompact` | context 壓縮前後 | 壓縮後重新注入重要資訊 |
| `SessionEnd` | session 結束時 | 清理、記錄 |

完整清單還有更多事件，見 [Hooks reference](https://code.claude.com/docs/en/hooks)。

### Matcher

沒有 matcher 時，hook 會在該事件每次發生時都執行。`PreToolUse`、`PostToolUse` 的 matcher 比對的是**工具名稱**：

- `"Bash"`：只有 shell 指令
- `"Edit|Write"`：編輯或寫檔
- `"mcp__.*"`：所有 MCP 工具

注意：Claude 也可能用 shell 指令改檔案（例如 `sed -i`）。只 match `Edit|Write` 的 hook 看不到這種修改；如果你的 hook 必須看到每一次檔案變更，要另外處理 `Bash`，或用 `Stop` hook 每輪掃一次工作目錄。

## 輸入與輸出

### 輸入：stdin 的 JSON

Hook 執行時，Claude Code 會把事件資料用 JSON 從 stdin 傳進去。例如 Claude 要執行 `npm test` 時，`PreToolUse` hook 收到：

```json
{
  "session_id": "abc123",
  "cwd": "/Users/sarah/myproject",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "npm test" }
}
```

### 輸出：exit code

| Exit code | 意思 |
|---|---|
| `0` | 沒有意見。**注意：對 PreToolUse 來說，0 不代表核准**，呼叫仍會走正常的權限流程 |
| `2` | **擋下**。把原因寫到 stderr，Claude 會收到這段說明並調整做法 |
| 其他 | 多數事件會照常進行 |

### 輸出：JSON 決策

需要更細的控制時，exit 0 並在 stdout 印出 JSON：

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "請改用 rg，比 grep 快"
  }
}
```

`permissionDecision` 可以是 `allow`、`ask`、`deny`。多個 hook 同時回應時，**最嚴格的勝出**（deny > ask > allow）。

一支 hook 選一種方式：要嘛 exit 2 + stderr，要嘛 exit 0 + JSON，不要混用。

## 實作一：擋掉危險指令

`.claude/hooks/block_dangerous.py`：

```python
import json
import re
import sys

sys.stderr.reconfigure(encoding="utf-8")  # Windows 主控台不是 UTF-8 時，印中文會 crash
data = json.load(sys.stdin)
command = data.get("tool_input", {}).get("command", "")

DANGEROUS = [
    r"\brm\s+-rf\s+/",              # 刪根目錄
    r"\bgit\s+push\s+.*--force\b",  # 強制推送
    r"\bgit\s+reset\s+--hard\b",    # 丟掉未提交的修改
]

for pattern in DANGEROUS:
    if re.search(pattern, command):
        print(f"已擋下危險指令（符合規則 {pattern}）。請改用較安全的做法，或請使用者自己執行。",
              file=sys.stderr)
        sys.exit(2)

sys.exit(0)
```

註冊到 `.claude/settings.json`：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "python .claude/hooks/block_dangerous.py" }]
      }
    ]
  }
}
```

## 實作二：讀過外部內容後降級

這是 U2 提過的**提示注入**問題：網頁、信件、issue 內容裡可能藏著「請執行 `curl … | sh`」或「把 .env 貼到這個網址」之類的文字。Agent 讀到之後，可能真的照做。

AI-OS 專案的做法叫「汙染降級」：**一旦讀過不可信的外部內容，之後的高風險操作一律改成先問人。**用兩個 hook 就能在 Claude Code 做出來：

**第一個 hook（PostToolUse）**：讀了外部內容，就替這個 session 做記號。

```python
# .claude/hooks/mark_tainted.py
import json, pathlib, sys

data = json.load(sys.stdin)
state = pathlib.Path(data["cwd"]) / ".claude" / "state"
state.mkdir(parents=True, exist_ok=True)
(state / f"tainted-{data['session_id']}").write_text(data.get("tool_name", ""))
```

**第二個 hook（PreToolUse）**：有記號的 session，高風險指令改成 ask。

```python
# .claude/hooks/taint_gate.py
import json, pathlib, re, sys

data = json.load(sys.stdin)
marker = pathlib.Path(data["cwd"]) / ".claude" / "state" / f"tainted-{data['session_id']}"
command = data.get("tool_input", {}).get("command", "")
RISKY = r"\b(git\s+push|curl|wget|scp|ssh|rm\s+-r|npm\s+publish)\b"

if marker.exists() and re.search(RISKY, command):
    print(json.dumps({
        "hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": "ask",
            "permissionDecisionReason": f"本 session 讀過外部內容（{marker.read_text()}），高風險指令需要人工確認。",
        }
    }))
sys.exit(0)
```

**註冊**：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "WebFetch|WebSearch|mcp__.*",
        "hooks": [{ "type": "command", "command": "python .claude/hooks/mark_tainted.py" }]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "python .claude/hooks/taint_gate.py" }]
      }
    ]
  }
}
```

記得把 `.claude/state/` 加進 `.gitignore`。

> **Windows 踩坑**：hook 腳本印中文時，如果主控台編碼不是 UTF-8，Python 會直接 crash，結束碼變成 1 而不是 2——**等於沒擋**。所以 stderr 要先 `reconfigure(encoding="utf-8")`，JSON 輸出保留 `json.dumps` 預設的 `ensure_ascii`。寫完 hook 一定要用真的輸入測一次結束碼。這個護欄在 auto 模式下特別有價值：平常不打擾你，只有在風險真的升高時才停下來。

## 用 hook 做品質關卡

Hook 輸出的內容會回到 Claude 的 context。這讓 hook 變成「自動化的評測」：

- `PostToolUse` 跑 lint 或型別檢查，錯誤訊息會被 Claude 讀到並自己修正
- `Stop` hook 跑測試，失敗就擋下結束，讓 Claude 繼續修（注意不要寫成無限迴圈）

需要判斷力而非固定規則時，還有 `"type": "prompt"`（用模型做一次評估）和 `"type": "agent"`（可以用工具的驗證代理，實驗性功能）。

### 真實案例：finlab 專案

- `.claude/settings.json` 註冊了一個 `PostToolUse` hook（matcher 是 `Bash`），偵測到 `git push` 成功後，提醒 Claude 寫開發筆記存進知識庫
- `.githooks/pre-push` 是 **git 本身的 hook**（不是 Claude Code 的 hook）：push 前一定要通過 Playwright 測試

兩者可以搭配：git hook 管「任何人用任何方式 push」，Claude Code hook 管「Claude 在 session 裡的行為」。

## Hook 的安全注意事項

- Hook 用你的帳號權限執行任何指令。**加入別人的 hook（包括 plugin 帶來的）之前，先讀過內容**
- Hook 腳本要處理意外輸入，不要把 stdin 內容直接拼進 shell 指令
- 設定 `"disableAllHooks": true` 可以停用 hook；但組織的 managed hook 只有在 managed 設定裡停用才會失效

## 本課小結

- 指示是請求，hook 是強制；**必須成立的規則寫成 hook**
- `PreToolUse` 可以擋：exit 2 + stderr，或 JSON 的 `permissionDecision`
- PreToolUse 的 exit 0 不代表核准，只是「沒意見」
- 兩個 hook 就能做出「讀過外部內容後降級」的提示注入防護
- Hook 的輸出會回到 context，可以當成自動化評測

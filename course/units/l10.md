# L10 期末專題：my-claude-toolkit

> 本課目標：把整套課程學到的東西整合成一個**你真的會每天使用**的 plugin，並整理一份可以帶回團隊的 AI-SDLC 原則清單。完成後送出專題，審核通過即核發結業證書。

## 專題要求

建立一個 plugin repo（建議命名 `my-claude-toolkit`），並放進一個 marketplace。最低要求：

| 項目 | 要求 |
|---|---|
| 擴充點 | 至少包含 **skill、hook、subagent、MCP 其中三種** |
| 護欄 | 至少一個 `PreToolUse` hook 做安全把關 |
| 打包 | `claude plugin validate` 通過 |
| 發布 | 有 `marketplace.json`，可以在另一個專案用 `claude plugin install` 裝起來 |
| 文件 | README 說明每個元件做什麼、為什麼用這個機制 |
| 原則清單 | 一份 `PRINCIPLES.md`（見下方） |

## 建議的起步方式

1. **從痛點出發**：列出過去兩週你重複對 Claude 說的話、重複做的流程、讓你不放心的操作
2. **逐條對應機制**：用附錄的速查表決定每一條該用什麼
3. **先在一個專案的 `.claude/` 做出來**，確定好用再搬進 plugin（L8 的轉換步驟）

### 範例需求清單

| 痛點 | 機制 | 理由 |
|---|---|---|
| 每次都要提醒它跑測試再 commit | CLAUDE.md | 每次都該知道的規則 |
| 每天下班要寫日報 | skill（`disable-model-invocation`） | 固定流程、由我觸發 |
| 怕它 `git push --force` | PreToolUse hook | 必須強制，不能靠提示詞 |
| 審查程式碼時 context 被塞爆 | subagent（唯讀工具） | context 隔離、限制能力 |
| 要查公司知識庫 | MCP | 外部系統 |
| 讀了網頁之後要更小心 | PostToolUse + PreToolUse hook | 汙染降級護欄 |

## PRINCIPLES.md：帶回團隊的原則

整理 5–10 條**不綁定特定工具**的原則，每條包含：原則、理由、在 Claude Code 的做法、換成其他工具時要找什麼。範例：

```markdown
## 1. 必須成立的規則用確定性機制，不用提示詞
- 理由：模型會盡量遵守指示，但不保證；安全與合規不能靠「盡量」
- Claude Code：PreToolUse hook + 權限 deny 規則
- 其他工具：找它的 pre-execution hook、policy 或 allowlist 機制
```

其他可以思考的方向：

- 知識分層（永遠需要 vs 需要時才載入）
- 給 Agent 可以執行的驗證方式
- 大改動先規劃再執行
- 隔離 context 處理大量資訊
- 讀過不可信內容後提高警戒
- 設定進版控、像程式碼一樣審查
- 第三方擴充的供應鏈風險

- [ ] README 解釋了每個元件的機制選擇
- [ ] PRINCIPLES.md 至少 5 條

## 送出專題

在本頁下方的「期末專題」區塊填寫：

- **repo 網址**（https 開頭）
- **專題說明**：做了哪些元件、各解決什麼痛點、為什麼選這個機制、遇到什麼困難

送出後會先由 AI 助教給一份初審回饋（AI 服務可用時），再由管理員審核。審核通過後，你會拿到一組證書編號，任何人都可以用這組編號驗證。

> 送出專題的前提是所有必修單元（U1–U6、L8、L9）的測驗都已通過。

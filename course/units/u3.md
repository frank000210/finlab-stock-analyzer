# U3 記憶與 RAG：Skills

> **Agent 原理**：Agent 的記憶分層——永遠在場的「工作記憶」、需要時才檢索的「長期知識」。RAG（檢索增強生成）就是「先找出相關資料，再放進 context 讓模型回答」。
> **Claude Code 實作**：CLAUDE.md（永遠載入）、auto memory（自動筆記）、Skills（漸進式載入）。
> **本課實作**：做一個參考型 skill 和一個動作型 skill `/daily-report`。

## 記憶的三個層次

| 層次 | Claude Code 的對應 | 誰寫 | 何時載入 |
|---|---|---|---|
| 永遠需要的規則 | CLAUDE.md、rules | 你 | 每個 session 開頭 |
| 累積的經驗 | Auto memory | Claude 自己 | 每個 session 開頭（MEMORY.md 前 200 行或 25KB） |
| 偶爾才需要的知識與流程 | Skills | 你 | 用到時才載入完整內容 |

U1 學過：CLAUDE.md 越長越吃 context，遵循度也越差。**解法不是把東西刪掉，而是把「偶爾才需要」的部分搬進 skill。**

## Auto memory：Claude 自己做的筆記

當你糾正它、告訴它偏好時，Claude 可以把這些經驗記下來，下次 session 自動讀到。

- 存在 `~/.claude/projects/<專案>/memory/`，裡面有一個索引 `MEMORY.md` 和多個主題檔
- 同一個 git repo 的所有 worktree 共用一份
- 輸入 `/memory` 可以檢視與編輯

Auto memory 和 CLAUDE.md 都是「context，不是強制設定」。它們是筆記，不是規則引擎。

## Skill 是什麼

一個 skill 就是一個資料夾，裡面至少有一個 `SKILL.md`：

```text
.claude/skills/
└── daily-report/
    ├── SKILL.md        ← 必要：說明與指示
    ├── template.md     ← 選用：需要時才讀的參考資料
    └── scripts/
        └── collect.py  ← 選用：會被執行、不會被載入的腳本
```

`SKILL.md` 由兩部分組成：

```markdown
---
name: daily-report
description: 產生今日工作日報。使用者說「寫日報」「今天做了什麼」時使用。
---

1. 用 `git log --since=midnight --oneline` 列出今天的 commit
2. 依照 [template.md](template.md) 的格式整理
3. 最後列出明天待辦
```

上面 `---` 之間是 **frontmatter**（設定），下面是 Claude 執行時要遵循的指示。

### 存放位置

| 範圍 | 路徑 |
|---|---|
| 個人（所有專案） | `~/.claude/skills/<名稱>/SKILL.md` |
| 專案（進版控） | `.claude/skills/<名稱>/SKILL.md` |
| Plugin | `<plugin>/skills/<名稱>/SKILL.md`，呼叫時是 `/plugin名稱:skill名稱` |

## 漸進式載入：Skill 的 RAG

Skill 的關鍵設計是**漸進式載入（progressive disclosure）**：

1. **Session 開始**：只把每個 skill 的 `name` 和 `description` 放進 context（很便宜）
2. **用到時**：你輸入 `/daily-report`，或 Claude 判斷你的需求符合某個 description，才載入完整 `SKILL.md`
3. **更深入時**：SKILL.md 裡提到的 `template.md` 等支援檔，Claude 需要時才去讀

這就是 RAG 的精神：**先用便宜的摘要判斷相關性，再把真正需要的內容放進 context。**

建議 `SKILL.md` 控制在 500 行內，長的參考資料拆到支援檔。

## 寫出會被觸發的 description

Claude 是靠 `description` 決定要不要自動載入 skill。寫不好，就會該用的時候沒用、不該用的時候亂用。

| ❌ 太模糊 | ✅ 好的寫法 |
|---|---|
| 處理報告 | 產生今日工作日報。使用者說「寫日報」「今天做了什麼」時使用。 |
| API 相關 | 本專案的 REST API 撰寫規範與錯誤碼表。新增或修改 `src/api/` 底下的 endpoint 時使用。 |

原則：

- **最重要的使用情境放最前面**（description 加上 `when_to_use` 合計有 1,536 字元上限）
- 寫出**觸發的關鍵字**或典型請求
- 多個 skill 的描述**不要重疊**，否則 Claude 會選錯

## 參考型與動作型 skill

| 類型 | 用途 | 例子 | 建議設定 |
|---|---|---|---|
| 參考型 | 提供知識，Claude 工作時自動參考 | API 規範、命名慣例、資料庫 schema | `user-invocable: false`（不出現在 `/` 選單） |
| 動作型 | 執行一個流程 | `/deploy`、`/daily-report`、`/release` | 有副作用時設 `disable-model-invocation: true` |

### 重要的 frontmatter 欄位

| 欄位 | 作用 |
|---|---|
| `description` | 何時使用（強烈建議填） |
| `disable-model-invocation: true` | **只能由你手動 `/名稱` 呼叫**，Claude 不會自己觸發。部署、發訊息這類有副作用的流程一定要設 |
| `user-invocable: false` | 從 `/` 選單隱藏，只給 Claude 自動參考 |
| `allowed-tools` | 這個 skill 執行的那一輪，哪些工具不用問就能用，例如 `Bash(git log *)` |
| `argument-hint` | 參數提示，例如 `[issue-number]` |
| `context: fork` | 在獨立的 subagent 中執行（U5） |
| `paths` | 只在處理符合的檔案時才自動載入 |

`disable-model-invocation: true` 還有一個好處：它的 description 不會放進 context，**完全不佔空間**，直到你呼叫它。

## 參數與動態注入

### 參數

呼叫時可以帶參數：`/fix-issue 123`。在 SKILL.md 裡用：

- `$ARGUMENTS`：全部參數
- `$0`、`$1`…：第幾個參數
- 在 frontmatter 宣告 `arguments: [issue]` 後，可以用 `$issue`

### 動態注入 `` !`指令` ``

在 SKILL.md 裡寫 `` !`git diff HEAD` ``，Claude Code 會**在送給模型之前先執行這個指令**，把輸出貼進去。模型看到的是實際結果：

```markdown
## 目前狀態
- 分支：!`git branch --show-current`
- 未提交的變更：!`git status --short || true`
```

注意：指令失敗（非 0 結束碼）會讓整個 skill 中止，可能失敗的指令後面加 `|| true`。

## 一個完整的動作型 skill

```markdown
---
name: daily-report
description: 產生今日工作日報。使用者說「寫日報」「今天做了什麼」時使用。
disable-model-invocation: true
allowed-tools: Bash(git log *) Bash(git diff --stat *)
---

## 今天的 commit
!`git log --since=midnight --pretty="- %s" || true`

## 今天改動的檔案
!`git diff --stat "HEAD@{midnight}" HEAD || true`

## 任務
根據上面的資料寫一份日報，格式：
1. **完成事項**：用一般人看得懂的話描述，不要直接貼 commit 訊息
2. **遇到的問題**
3. **明日待辦**
```

## 測試你的 skill

1. **開新 session 測試**（`/clear`）：寫 skill 時留下的對話內容，會掩蓋 skill 本身的問題
2. **比較有無 skill 的結果**：確定是 skill 帶來的改善
3. **測自動觸發**：用不同說法提出需求，看 Claude 會不會選到它
4. **審查來自別人的 skill**：特別是 `allowed-tools`，skill 可以替自己開很大的權限

## 本課小結

- 記憶分三層：永遠在場（CLAUDE.md）、自動累積（auto memory）、需要才載入（skill）
- Skill 的漸進式載入就是 RAG：先看描述，用到才讀全文
- description 決定觸發準不準：情境放前面、寫出關鍵字、彼此不重疊
- 有副作用的流程一定要 `disable-model-invocation: true`

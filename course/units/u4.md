# U4 規劃與推理：Agent Loop

> **Agent 原理**：ReAct（Reason + Act）——模型交替「思考下一步」與「採取行動」，並觀察結果修正方向。
> **Claude Code 實作**：Agent 迴圈、plan mode、todo 清單、checkpoint / rewind。
> **本課實作**：拆解一次 session 的完整軌跡，並用 plan mode 完成一個小功能。

## ReAct：想 → 做 → 看結果

早期的 LLM 應用是「一問一答」。ReAct 讓模型變成一個迴圈：

```text
思考：要修這個 bug，我得先知道哪個測試失敗
行動：執行 npm test
觀察：test/auth.test.js 第 42 行失敗，token 過期判斷錯誤
思考：去看 src/auth.js 的過期判斷
行動：讀 src/auth.js
……（重複，直到完成）
```

每一次「觀察」都是新的資訊，讓下一次「思考」更準。這就是 Agent 和聊天機器人的根本差異。

## Claude Code 的 Agent 迴圈

官方把迴圈描述成三個階段：

1. **蒐集 context**（gather context）：搜尋、讀檔、看 git 狀態
2. **採取行動**（take action）：編輯檔案、執行指令
3. **驗證結果**（verify results）：跑測試、檢查輸出

這三個階段會交錯、重複，直到任務完成。迴圈由兩個部分驅動：**負責推理的模型**和**負責行動的工具**；Claude Code 就是包在模型外面、提供工具並管理 context 的那一層（harness）。

**你也是迴圈的一部分**：

- 按 **Esc** 立刻停下目前的動作
- 直接輸入修正並按 Enter，訊息會排隊，等手上的工具呼叫結束後它就會讀到並調整

## 讓 Agent 能自我驗證

迴圈的第 3 步「驗證」做得好不好，決定了結果的品質。所以描述任務時，**告訴它怎麼確認做對了**：

| ❌ 只說目標 | ✅ 附上驗證方式 |
|---|---|
| 修好登入的 bug | 修好登入的 bug，`npm test -- auth` 要全部通過 |
| 加一個匯出 CSV 功能 | 加匯出 CSV 功能，用 `sample.json` 匯出後欄位要跟表頭一致 |
| 讓頁面載入快一點 | 首頁的 API 請求從 8 個減到 3 個以下，用瀏覽器 Network 面板確認 |

有可以執行的檢查，Agent 就能自己跑「改 → 測 → 再改」的迴圈，而不是改完就交差。

## Plan mode：先規劃再動手

大改動直接動手，常常改到一半發現方向錯了。**Plan mode** 讓 Claude 只讀、只探索、不修改原始碼，最後提出一份計畫給你確認。

進入方式：按 **Shift+Tab** 切換到 Plan 模式，或在設定裡設 `defaultMode: "plan"`。

適合使用的時機：

- 改動會跨很多檔案
- 你還不確定要怎麼做，想先看它的理解對不對
- 進入陌生的程式碼庫

計畫確認後，切回其他模式讓它執行。**花五分鐘審計畫，常常能省下一小時的重工。**

## Todo 清單：把大任務拆小

處理多步驟任務時，Claude 會建立 todo 清單，逐項標記進行中與完成。按 **Ctrl+T** 可以顯示或隱藏清單。

這對應到 Agent 研究裡的「任務分解」：把模糊的大目標拆成可驗證的小步驟，每完成一步就有一個檢查點。你可以在它開始前看清單，發現漏掉的步驟就直接補充。

## Checkpoint 與 rewind：退回錯誤

Claude 編輯檔案之前，會先替這個檔案拍快照。做錯了：

- **Esc 連按兩下**，或輸入 `/rewind`：選擇要退回到哪一則訊息之前的狀態
- 也可以直接說「把剛剛的修改退回去」

Checkpoint 有明確的限制：

- **只涵蓋檔案修改**
- **碰到外部系統的動作無法退回**：資料庫寫入、API 呼叫、部署、已經 push 的 commit
- 這些只能靠 permission mode 與權限規則**事前**把關（U2）

所以 checkpoint 不能取代 git。好習慣是：重要的節點 commit 一次，checkpoint 用來處理對話中的小失誤。

## Session 的延續

- 每個 session 從空白的 context 開始，不會記得上一次的對話
- `claude --continue`：接續最近一次 session
- `claude --resume`：從清單選一個 session 接續
- 要跨 session 保留的東西，寫進 CLAUDE.md 或交給 auto memory（U3）

## 本課小結

- ReAct = 想 → 做 → 看結果；Claude Code 的迴圈是蒐集 → 行動 → 驗證
- 給它**可以執行的驗證方式**，它才能自我修正
- 大改動先用 plan mode 規劃，Shift+Tab 切換
- Checkpoint 只能退回檔案修改；外部系統的動作要靠權限事前把關

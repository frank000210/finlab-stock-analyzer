# L8 Plugins：打包你的設定

> **原理**：好的設定要能重複使用。把散落在 `.claude/` 的 skill、subagent、hook、MCP 收成一個單位，才能跨專案安裝、版本管理、分享給別人。
> **Claude Code 實作**：`.claude-plugin/plugin.json`、`--plugin-dir`、`claude plugin validate`、命名空間。
> **本課實作**：把 U3–U6 做的成品打包成一個 plugin。

## 什麼時候需要 plugin

Skill、subagent、hook、MCP 放在專案的 `.claude/` 底下就能用。只服務一個專案、只有你在用的時候，**不需要 plugin**。

需要 plugin 的時機：

- 第二個 repo 也要同一套設定
- 要分享給同事
- 要發布有版本號的更新

## Plugin 的目錄結構

```text
my-toolkit/
├── .claude-plugin/
│   └── plugin.json        ← 必要：plugin 的名片（manifest）
├── skills/
│   └── daily-report/
│       └── SKILL.md
├── agents/
│   └── code-reviewer.md
├── hooks/
│   └── hooks.json
├── output-styles/
│   └── coach.md
└── .mcp.json
```

最常見的錯誤：**只有 `plugin.json` 放在 `.claude-plugin/` 裡面**。skills、agents 等資料夾要放在 plugin 根目錄，放進 `.claude-plugin/` 不會被載入。

## plugin.json

```json
{
  "name": "my-toolkit",
  "description": "我的 Claude Code 工具組：日報、程式審查、安全護欄",
  "version": "1.0.0",
  "author": { "name": "Your Name" }
}
```

| 欄位 | 說明 |
|---|---|
| `name` | 必填，不能有空格。會變成每個 skill 和 agent 的前綴 |
| `description` | 在 `/plugin` 裡顯示的說明 |
| `version` | 選填。有設定時，使用者會停在這個版本，直到你改版號 |
| `author` | 作者，裡面的 `name` 必填 |

## 命名空間

Plugin 裡的 skill 和 agent 會自動加上 plugin 名稱當前綴：

| 原本 | 在 plugin 裡 |
|---|---|
| `/daily-report` | `/my-toolkit:daily-report` |
| subagent `code-reviewer` | `my-toolkit:code-reviewer` |

好處是兩個 plugin 都有 `review` skill 也不會衝突。

**Hook 沒有命名空間**：如果同一個 hook 同時留在 `.claude/settings.json` 又放進 plugin 的 `hooks/hooks.json`，每次事件會執行兩次。

## 把現有的 .claude/ 轉成 plugin

在專案根目錄執行：

```bash
mkdir -p my-toolkit/.claude-plugin
# 寫好 my-toolkit/.claude-plugin/plugin.json 後：
cp -r .claude/skills my-toolkit/
cp -r .claude/agents my-toolkit/
mkdir -p my-toolkit/hooks
```

Hook 的轉法：建立 `my-toolkit/hooks/hooks.json`，把 settings 檔裡整個 `hooks` 物件搬進去，格式完全一樣：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "python \"${CLAUDE_PLUGIN_ROOT}/hooks/block_dangerous.py\"" }
        ]
      }
    ]
  }
}
```

注意指令裡的 `${CLAUDE_PLUGIN_ROOT}`：plugin 安裝後會被放在快取目錄，路徑跟你開發時不一樣。**plugin 裡引用自己的檔案，一律用 `${CLAUDE_PLUGIN_ROOT}` 開頭。**

確認 plugin 正常後，記得刪掉 `.claude/` 裡的原始檔與 settings 裡的 hooks，避免重複載入。

## 測試與除錯

### 1. 驗證格式

```bash
claude plugin validate ./my-toolkit
```

會檢查 manifest 與每個 skill、agent 的 frontmatter，最後印出 `✔ Validation passed` 才算通過。

### 2. 載入測試

```bash
claude --plugin-dir ./my-toolkit
```

`--plugin-dir` 只在這個 session 載入 plugin，不會安裝、不會寫進設定。進去之後：

- 輸入 `/my-toolkit:daily-report` 測 skill
- 請 Claude「用 my-toolkit:code-reviewer 審查最近的修改」測 subagent
- 觸發 hook 對應的事件測 hook

### 3. 改完重新載入

在 session 裡輸入 `/reload-plugins`，不用重開就能套用修改。

### 4. 看錯誤

輸入 `/plugin`，**Installed** 分頁列出載入成功的元件，**Errors** 分頁列出失敗的原因（例如路徑不存在）。

### 5. 測行為

Plugin 載入成功不代表它真的有讓 Claude 做得更好。`claude plugin eval` 可以用測試案例比較「有裝」和「沒裝」的差異（進階內容，見延伸閱讀）。

## 本課小結

- 一個專案自己用不需要 plugin；要跨專案、分享、版本管理才需要
- 只有 `plugin.json` 放在 `.claude-plugin/`，其他元件放根目錄
- Skill 和 agent 有命名空間，hook 沒有
- Plugin 內的路徑用 `${CLAUDE_PLUGIN_ROOT}`
- `validate` → `--plugin-dir` → `/reload-plugins` → `/plugin` 的 Errors 分頁

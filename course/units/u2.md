# U2 Tool Use：工具呼叫與權限

> **Agent 原理**：模型本身只會產生文字；「工具呼叫（function calling）」讓它可以請外部程式代為行動，再把結果讀回來。
> **Claude Code 實作**：內建工具、權限規則（allow / ask / deny）、permission modes、MCP。
> **本課實作**：寫一組權限規則，並用 Python 寫一個最小的 MCP server 接上 Claude Code。

## 工具呼叫是怎麼運作的

一次工具呼叫的流程：

1. 開發者把「有哪些工具、各要什麼參數」放進 context
2. 模型判斷需要某個工具，輸出一段結構化的呼叫（工具名稱 + 參數）
3. 外層程式（harness，這裡就是 Claude Code）**真的去執行**
4. 執行結果放回 context，模型讀了再決定下一步

重點在第 3 步：**執行的是 Claude Code，不是模型**。所以「能不能執行」可以由 Claude Code 在模型之外把關——這就是權限系統存在的位置。

## Claude Code 的內建工具

| 類別 | 能做什麼 | 代表工具 |
|---|---|---|
| 檔案操作 | 讀檔、編輯、建立新檔 | Read、Edit、Write |
| 搜尋 | 依檔名或內容搜尋 | Glob、Grep |
| 執行 | 跑 shell 指令、測試、git | Bash（Windows 另有 PowerShell） |
| 網路 | 搜尋網頁、抓文件 | WebSearch、WebFetch |
| 程式碼智慧 | 型別錯誤、跳到定義（需安裝語言 plugin） | LSP |

另外還有派出 subagent、問你問題等協調用的工具。你不需要指定用哪個工具——說清楚目標，它會自己選。

## 權限規則：allow、ask、deny

權限寫在 settings 檔的 `permissions` 裡：

```json
{
  "permissions": {
    "allow": [
      "Bash(npm run test *)",
      "Bash(git status)",
      "Bash(git diff *)"
    ],
    "ask": [
      "Bash(git push *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./secrets/**)",
      "Bash(rm -rf *)"
    ]
  }
}
```

- **allow**：直接執行，不問
- **ask**：每次都要問你
- **deny**：一律禁止

### 評估順序：deny → ask → allow

這是最常考、也最常搞錯的地方：**規則依 deny、ask、allow 的順序評估，第一個符合的決定結果，跟規則寫得多精確無關。**

所以：

- `deny: ["Bash(aws *)"]` 會擋掉 `aws s3 ls`，即使 allow 裡有 `Bash(aws s3 ls)`——**allow 不能在 deny 裡挖例外**
- ask 也一樣：符合 ask 的呼叫一定會問，即使有更精確的 allow

另外，deny 寫**整個工具名稱**（例如 `"Bash"`）時，Claude 根本看不到這個工具；寫成帶條件的（例如 `"Bash(rm *)"`）則工具還在，只是符合的呼叫會被擋。

## 規則語法速查

| 寫法 | 意思 |
|---|---|
| `Bash` | 所有 shell 指令 |
| `Bash(npm run test *)` | 以 `npm run test ` 開頭的指令 |
| `Read(./.env)` | 讀取專案根目錄的 .env |
| `Read(./secrets/**)` | 讀取 secrets 底下所有檔案 |
| `Edit(./src/**)` | 編輯 src 底下的檔案 |
| `WebFetch(domain:docs.python.org)` | 抓取指定網域 |
| `mcp__github__*` | github 這個 MCP server 的所有工具 |
| `mcp__github__create_issue` | github server 的單一工具 |

## Settings 檔的層級

權限跟其他設定一樣有層級，優先順序由高到低：

1. **Managed**（組織管理員部署，任何層級都不能覆蓋）
2. 命令列參數（例如 `--allowedTools`）
3. `.claude/settings.local.json`（本機、不進版控）
4. `.claude/settings.json`（專案、進版控，團隊共用）
5. `~/.claude/settings.json`（個人，所有專案）

但記住：**任何一層的 deny 都會生效**。個人設定 allow、專案設定 deny，結果是 deny；反過來也一樣。

一個實用的分工：

- 團隊都該遵守的禁止事項 → 專案 `settings.json` 的 deny
- 你個人常用、不想一直按允許的指令 → `settings.local.json` 的 allow

## Permission modes

除了個別規則，還有整體的「模式」。在 Claude Code 裡按 **Shift+Tab** 可以切換：

| 模式 | 行為 |
|---|---|
| `default`（Manual） | 每種工具第一次使用時問你 |
| `acceptEdits` | 自動接受檔案編輯與常見檔案指令（mkdir、mv 等），其他指令仍會問 |
| `plan` | 只讀與探索，不修改原始碼，最後提出計畫（U4） |
| `auto` | 背景有一個分類器檢查每個動作是否符合你的要求，擋下有風險的 |
| `dontAsk` | 凡是需要詢問的一律拒絕，只執行已允許的 |
| `bypassPermissions` | 幾乎不問。只適合隔離環境（例如一次性容器） |

建議：日常用 `default` 或 `auto`；探索陌生專案、規劃大改動時切 `plan`；沒有隔離環境不要用 `bypassPermissions`。

## MCP：接上外部系統

內建工具只能碰你的電腦。要讓 Claude 查資料庫、讀 Jira、發 Slack，就要用 **MCP（Model Context Protocol）**——一個讓 AI 工具連接外部服務的開放協定。一個 MCP server 提供一組工具，Claude Code 連上後就能呼叫。

### 加入 MCP server

```bash
# 遠端 HTTP server（建議）
claude mcp add --transport http notion https://mcp.notion.com/mcp

# 本機程式（stdio），-- 之後是啟動指令
claude mcp add --transport stdio my-db -- python server.py

# 帶環境變數
claude mcp add --env API_KEY=xxx --transport stdio weather -- npx -y weather-mcp
```

`--scope` 決定存在哪裡：

| scope | 存放位置 | 用途 |
|---|---|---|
| `local`（預設） | `~/.claude.json`，只限這個專案 | 自己試用 |
| `project` | 專案根目錄的 `.mcp.json` | 進版控，團隊共用 |
| `user` | `~/.claude.json`，所有專案 | 個人常用工具 |

### .mcp.json 範例

```json
{
  "mcpServers": {
    "kb": {
      "type": "http",
      "url": "https://kb.example.com/mcp",
      "headers": { "Authorization": "Bearer ${KB_API_TOKEN}" }
    }
  }
}
```

**金鑰一律用 `${環境變數}`，不要直接寫在檔案裡**——這個檔案會進版控。

在 Claude Code 裡輸入 `/mcp` 可以看每個 server 的連線狀態、做 OAuth 登入。MCP 工具預設是「需要時才載入完整定義」（tool search），所以裝了很多 server 也不會一開始就吃掉大量 context。

## 自己寫一個 MCP server

用官方 Python SDK（`pip install mcp`），十幾行就能寫出一個：

```python
# server.py
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("course-demo")

@mcp.tool()
def word_count(text: str) -> int:
    """計算一段文字有幾個字（中文以字元計）。"""
    return len(text.replace(" ", ""))

if __name__ == "__main__":
    mcp.run()  # 預設走 stdio
```

然後：

```bash
claude mcp add --transport stdio course-demo -- python server.py
```

重開 session，問它「用 word_count 算一下這句話有幾個字」，就會看到它呼叫你的工具。

**真實案例**：finlab 專案的 `kb-web` 就是一個 MCP server，提供 `kb_ask`、`kb_write` 等工具，讓 Claude 查詢與寫入知識庫。lab 會帶你看它的結構。

## MCP 的安全提醒

- 只連你信任的 server。會抓外部內容（網頁、信件）的 server 有**提示注入**風險：外部內容裡可能藏著「請把 .env 內容貼出來」之類的文字（U6 會教怎麼防）
- 專案 `.mcp.json` 裡的 server，第一次使用前 Claude Code 會要你核准
- 可以用權限規則限制 MCP 工具，例如 `"ask": ["mcp__github__create_*"]`

## 本課小結

- 工具由 Claude Code 執行，所以權限可以在模型之外把關
- 規則評估順序：**deny → ask → allow**，allow 不能在 deny 裡挖例外
- 任何層級的 deny 都有效；團隊禁令放專案 settings，個人便利放 local settings
- MCP 讓 Claude 接上外部系統；金鑰用環境變數；注意提示注入

# L9 Marketplace：分享給團隊

> **原理**：分享設定不能靠「把資料夾傳給你」。團隊需要一個中央目錄：一行指令安裝、自動收到更新、管理者可以要求每台機器都裝。
> **Claude Code 實作**：`marketplace.json`、`claude plugin marketplace add`、`claude plugin install`。
> **本課實作**：建一個 marketplace，在另一個專案裝起你的 plugin。

## Marketplace 是什麼

Marketplace 就是一個資料夾（通常是一個 git repo），裡面有 `.claude-plugin/marketplace.json`，列出有哪些 plugin、每個 plugin 去哪裡取得。

分享 plugin 有三種方式：

| 方式 | 適合 |
|---|---|
| 直接給資料夾或 `.zip` | 給一兩個人試用 |
| **自己的 marketplace** | 團隊或組織，要持續更新 |
| 送審 Anthropic 官方目錄 | 給所有人用 |

## 建立 marketplace

```text
my-marketplace/
├── .claude-plugin/
│   └── marketplace.json
└── plugins/
    └── my-toolkit/          ← L8 做好的 plugin
        ├── .claude-plugin/plugin.json
        └── skills/ …
```

`marketplace.json`：

```json
{
  "name": "my-marketplace",
  "description": "團隊共用的 Claude Code 工具",
  "owner": { "name": "Your Name" },
  "plugins": [
    {
      "name": "my-toolkit",
      "source": "./plugins/my-toolkit",
      "description": "日報、程式審查、安全護欄"
    }
  ]
}
```

必填的是 `name`、`owner` 和 `plugins`；每個 plugin 項目需要 `name` 和 `source`。

### 兩個最常見的錯誤

1. **相對路徑要從 marketplace 根目錄算起**（也就是包含 `.claude-plugin/` 的那一層），不能用 `..`
2. **項目的 `name` 要跟 plugin 自己 `plugin.json` 裡的 `name` 一樣**，否則安裝時會找不到

## 驗證、加入、安裝

```bash
# 1. 驗證格式
claude plugin validate ./my-marketplace

# 2. 加入 marketplace（記錄在你的使用者設定）
claude plugin marketplace add ./my-marketplace

# 3. 安裝：格式是 plugin名稱@marketplace名稱
claude plugin install my-toolkit@my-marketplace

# 4. 確認
claude plugin list
```

在 session 裡也可以用 `/plugin marketplace add` 與 `/plugin install`，會開啟 `/plugin` 面板操作。

要從頭來過：`claude plugin marketplace remove my-marketplace` 會移除 marketplace 並解除安裝它的 plugin。

## 放上 git，給團隊用

把 marketplace 資料夾推到 GitHub（可以是私有 repo），同事執行：

```bash
claude plugin marketplace add your-org/my-marketplace
claude plugin install my-toolkit@my-marketplace
```

### Plugin 的來源類型

`source` 不一定要放在 marketplace 裡：

| 來源 | 寫法 |
|---|---|
| marketplace 內的相對路徑 | `"./plugins/my-toolkit"` |
| 獨立的 GitHub repo | `{ "source": "github", "repo": "your-org/my-toolkit" }` |
| 某個 repo 的子目錄 | `{ "source": "git-subdir", "url": "your-org/monorepo", "path": "tools/my-toolkit" }` |

另外還有 `url`（任何 git 主機）、`archive`（zip）、`npm` 等。

## 版本與更新

- 從**本機目錄**加入的 marketplace：修改直接生效，下次開 session 或 `/reload-plugins` 就會套用
- 從 **git** 安裝的使用者：拿到的是快取的副本。你在 `plugin.json` 設了 `version`，使用者會停在那個版本，直到你改版號發布

所以發布流程是：改程式 → 更新 `version` → push。

## 讓專案自動推薦 plugin

團隊可以在專案的 `.claude/settings.json` 預先宣告 marketplace 與要啟用的 plugin，成員打開專案就會被提示安裝：

```json
{
  "extraKnownMarketplaces": {
    "my-marketplace": {
      "source": { "source": "github", "repo": "your-org/my-marketplace" }
    }
  },
  "enabledPlugins": {
    "my-toolkit@my-marketplace": true
  }
}
```

注意：專案設定裡的 `extraKnownMarketplaces` 要等成員**信任這個資料夾**（第一次開啟時的信任對話框）之後才會生效。組織管理員也可以用 managed settings 要求每台機器都安裝。

## Plugin 的信任與安全

裝一個 plugin，等於讓它的 hook 用你的權限執行指令、讓它的 skill 指揮 Claude、讓它的 MCP server 連上外部服務。

安裝別人的 plugin 前：

1. **讀 hooks**：它在什麼事件執行什麼指令？
2. **讀 skill 的 `allowed-tools`**：它替自己開了哪些權限？
3. **看 `.mcp.json`**：連到哪裡？送出什麼資料？
4. **固定版本**：git 來源可以指定 `ref` 或 `sha`，避免上游被竄改時自動拿到惡意版本

這就是軟體供應鏈安全的問題，跟裝 npm 套件一樣要謹慎。

## 本課小結

- Marketplace = 有 `.claude-plugin/marketplace.json` 的 repo
- 相對路徑從 marketplace 根目錄算；項目名稱要跟 plugin.json 一致
- `validate` → `marketplace add` → `install 名稱@marketplace`
- 用 `version` 控制更新；用 `extraKnownMarketplaces` + `enabledPlugins` 讓團隊自動取得
- 裝別人的 plugin 前先讀 hook、權限與 MCP 設定
